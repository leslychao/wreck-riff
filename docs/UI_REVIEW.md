# Визуальная проверка интерфейса

`--dev --ui-review` проходит существующие `GameApplication`, `ScreenFlow`, `MenuView` и `HudView`. Это отдельный автоматический диагностический режим: его нельзя совмещать с smoke, soak, benchmark или showcase. Внешние клавиши, мышь и hover не управляют сценарием. Графическое окно обязательно.

Пример после `installDist`, с Microsoft JDK 21:

```powershell
& 'C:/Users/vitalii/.jdks/ms-21.0.11/bin/java.exe' -cp 'build/install/wreck-riff/lib/*' game.wreckriff.Main --dev --ui-review --resolution=1280x720 --windowed --ui-scale=1
```

Каждый запуск использует новый каталог `WreckRiff/diagnostics/run-<uuid>` в штатном пользовательском каталоге. Существующие пользовательские настройки и прогресс не изменяются. Путь выводится как `DIAGNOSTIC_REPORT`. Основные результаты: `ui-review-manifest.json`, `diagnostic-result.json` и PNG в `captures/`.

Матрица разрешений: `640x480`, `1280x720`, `1920x1080`, `2560x1440`, `3440x1440`, `3840x1080`, `3840x2160`; прежние `720p` и `1080p` также работают. UI scale: `.8`, `1`, `1.5` (разрешены промежуточные значения). По умолчанию размеры от 1080 строк используют fullscreen, чтобы рамка окна не уменьшала клиентскую область; `--windowed` явно выбирает оконный режим. Без указанного размера UI review использует 1280x720 в окне. Если монитор/оконная система не предоставляет запрошенный framebuffer, режим пишет `FAIL`, а не принимает уменьшенную картинку.

Сценарий сохраняет fresh/unlocked главное меню и карты, прокрутку, три машины, четыре вкладки настроек, две вкладки управления, keep/manual rollback/автоматический десятисекундный rollback видео, повторное безопасное открытие подтверждения, титры, статистику, загрузку, ошибку, результаты и HUD. Для каждого из трёх профилей HUD показывает шесть выборов оружия, нулевой боезапас, ready/active/cooldown способностей, этажи/дальние/мёртвые цели радара, босса и несколько уведомлений. В конце проверяется возврат из настроек в паузу с сохранённой причиной.

Меню, вкладки, выбор машины, подтверждения и настройки видео выполняют настоящие обработчики через общий dispatch. Навигация по ID пользуется тем же focus/scroll owner, что клавиатура. Отдельные входные данные для результатов, HUD и unlock-состояния явно обозначены как `render-only fixture`: они не передаются `MatchRuntime` или записи прогресса. Это не доказательство победы в бою, работоспособности физического геймпада или окончательной визуальной приёмки. `storedWins` и `storedMatches` в manifest показывают состояние реального изолированного progress store; тестовые результаты туда не записываются.

Прокрутка клавиатурных назначений выбирает последнюю запись из `SettingsStore.defaultKeys()` (сейчас `Recover`). Фиксированный ESC не образует строку `binding:Pause`; `pad:Pause` существует только на вкладке геймпада. Арены, рекорды и машины в каталоге проверяются по реальным repository catalogues в unit-тестах.

Capture запрашивается после двух отрисованных кадров. Следующий шаг начинается после появления PNG с корректной сигнатурой и точным размером. Manifest ограничен 100 cases и хранит case ID, команды, fixture label, actual page/focus/scroll/framebuffer/scale, video state и путь PNG. Один case ограничен 20 секундами, весь сценарий — 240 секундами. Недоступные аппаратные действия обозначены `PENDING` с причиной. При ошибке остаются уже собранные данные и список незавершённых cases.

Успешный сбор заканчивается `CAPTURES_COMPLETE_HUMAN_REVIEW_PENDING`, `ownerAcceptance=NOT_GRANTED`, `releaseEligible=false`. Проверяющий затем открывает PNG и фиксирует замечания по конкретным case ID/размеру/масштабу. Автоматическое прохождение не означает отсутствие обрезанного текста или успешную визуальную приёмку.

Локальные unit-тесты проверяют options, временные границы scheduler, два кадра до capture, неверный framebuffer/PNG, таймаут, разделение fixtures и hardware evidence. Они не создают окно и не заменяют реальный просмотр матрицы.

Для окончательного Windows ZIP использовать существующий пакетный проверяющий:

```powershell
powershell -File tools/test-windows-package.ps1 -ZipPath <package.zip> -Mode UiReview -Resolution 1920x1080 -UiScale 1
```

Для оконных вариантов добавить `-Windowed`. Проверяющий распаковывает отдельную
копию ZIP, запрещает запись в установку, убирает внешнюю Java из PATH и запускает
фактический EXE. Уникальный отчёт `windows-package-UiReview-*.json` связывает
процесс, ZIP/JAR/source, manifest и SHA всех 67 PNG с запрошенным framebuffer,
масштабом и режимом окна. Аппаратный case должен оставаться `PENDING`, статистика
— нулевой. `CAPTURE_COLLECTION_COMPLETE` означает только завершённый сбор;
визуальный просмотр и приёмка владельца записываются отдельно.
