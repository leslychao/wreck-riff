# Диагностика кадров и контрольный benchmark

Короткий запуск собирает данные, но не подтверждает производительность релиза:

```powershell
.\build\distributions\WreckRiff\WreckRiff.exe --dev --seed=42 --ai-player --arena=construction_17 --benchmark-seconds=60
```

`diagnostic-result.json` сообщает `DIAGNOSTIC_COMPLETE` и `releaseEligible=false`.
Завершённый полный замер сообщает `BENCHMARK_MEASURED`. Это также не `PASS`: память
процесса проверяется внешним счётчиком Windows, а не размером Java heap.

Контроль отдельной карты выполняет существующий wrapper:

```powershell
.\tools\test-windows-benchmark.ps1 -Seconds 600 -Arena construction_17
```

Повторить для `neon_zero`, `euphoria_park`, `ash_necropolis`, `doomsday_arena`.
Wrapper пишет отдельные `build/reports/windows-benchmark-<arena>.json` и общий
`windows-benchmark.json` последнего запуска. Один отчёт не заменяет матрицу пяти карт.
Путь запуска wrapper пока указывает на app-image; проверкой окончательного ZIP
и привязкой всех артефактов к пакету управляет отдельный release gate.

Условия `PASS`: минимум 30 секунд активного прогрева, затем минимум 600 измеренных
секунд `ARENA_COMBAT`/`BOSS_COMBAT`; framebuffer 1920×1080, ровно MSAA 4, звук и
видимое окно, VSync выключен, подробное профилирование выключено; p95 ≤16,7 мс,
p99 ≤25 мс, ни одного боевого кадра >100 мс, нулевое потерянное время симуляции,
peak working set процесса ≤1,5 GiB. Для новых карт wrapper также требует наблюдение
обычного боя, босса, native-подброса и эффектов в измеренном интервале. Пиковое
число эффектов сохраняется; само наличие эффектов не доказывает насыщенность
сценария и не заменяет проверку предусмотренных боевых ситуаций.

Время измеряется монотонными часами между кадрами. Длительность относится к фазе
предыдущего отрисованного кадра. Кадр, пересекающий смену фазы, имеет категорию
`TRANSITION`; меню, загрузки, интро, вход босса, пауза и результаты имеют отдельные
гистограммы. Кадр, на котором завершился прогрев, целиком остаётся в прогреве.
Повторы матчей не сбрасывают собранные данные benchmark.

`phaseMetrics` хранит медиану, p95/p99, максимум и количества кадров >33/50/100 мс,
а также 32 самых тяжёлых кадра с номером кадра, tick, картой, фазой, числом участников,
физических тел, снарядов, эффектов, подбрасываемых машин и голосов SFX. Запись каждого
кадра на диск не выполняется. Загрузки и переходы исключены из боевых процентов,
но остаются в отчёте. Короткий benchmark также проверяется на пороги в данных отчёта;
успешное завершение процесса само по себе не означает прохождения порогов.

Подробная диагностика включается явно:

```powershell
.\build\distributions\WreckRiff\WreckRiff.exe --dev --seed=42 --ai-player --arena=construction_17 --benchmark-seconds=60 --profile
```

В диагностическом профиле сохраняется штатный `profile.jfr`, ограниченный 128 MiB
и двадцатью минутами истории. Используется конфигурация JDK `profile`: allocation,
GC, блокировки и файловый I/O. В JSON добавляются интервалы jME `AppProfiler`,
прикладные CPU-этапы и максимумы счётчиков renderer. Вложенные интервалы не суммируют:
`PRESENTATION` включает вложенные `HUD`/`AUDIO`, а `SIMULATION` включает этапы runtime.
GPU-время не измеряется этими CPU-интервалами; отсутствие отдельной GPU-записи
явно отмечено. Прогон с `--profile` никогда не подходит для итогового performance gate.
