# Wreck Riff

Локальный одиночный автомобильный бой для Windows x64. Пять двухуровневых арен с боссами объединены в кампанию; доступны отдельные бои и открываемые дуэли с боссами. Rivet, Grinder и Spark доступны сразу, различаются управлением, прочностью и собственной способностью SPECIAL. Общий арсенал — пулемёт, Homing, Power, Mine, Napalm, Ballistic, Cannon, Freeze и Shield.

Новые арены проходят без лимита времени. После обычных противников появляется босс, а разовый ремонт восстанавливает до 65% максимального HP выбранной машины. Dead Air Yard сохраняет отдельный бой против четырёх ботов с лимитом 6 минут. В компактном HUD оружие и способности показаны иконками; радар различает этажи и указывает направления дальних врагов. Итоги боя дополняет отдельный экран статистики. Названия новых арен, боссов и их реплики — русские; часть общего интерфейса остаётся английской.

Это реализация MVP, которая ещё проходит приёмку. Точные результаты проверок, известные ошибки и обязательные ручные проверки находятся в [ACCEPTANCE](docs/ACCEPTANCE.md) и [IMPLEMENTATION_STATUS](docs/IMPLEMENTATION_STATUS.md). Наличие исходников или ZIP само по себе не означает `MVP_ACCEPTED`.

## Запуск готового пакета

Распакуйте **весь** `WreckRiff-<версия>-windows-x64.zip` и запустите `WreckRiff/WreckRiff.exe`. Java 21 включена; пользователю не нужны Gradle, IDE или загрузка зависимостей. Сохраняйте каталоги `app`, `runtime`, `licenses` и `reports` рядом с EXE. Не запускайте его прямо из просмотрщика ZIP.

Сборка MVP не имеет цифровой подписи; Windows может показать предупреждение о неизвестном приложении. Подтверждённая платформа и отдельный тест Windows без установленной Java указаны в отчёте приёмки. Минимальные системные требования пока не установлены.

## Сборка из исходников

Нужны Windows x64, Git, PowerShell и **Microsoft Build of OpenJDK 21.0.11+10-LTS** с `java`, `javac`, `jlink`, `jpackage`. Лицензионные исходники runtime привязаны к этому выпуску. Первый запуск Gradle скачивает зафиксированные зависимости; ресурсы игры и исходники зависимостей уже находятся в репозитории. Проект использует Gradle Wrapper 8.14.3, jMonkeyEngine 3.8.1-stable и Minie 9.0.3. Системная Java 17 для сборки не подходит.

В PowerShell из корня репозитория выберите установленный JDK явно:

```powershell
$env:JAVA_HOME = 'C:\Users\vitalii\.jdks\ms-21.0.11'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
& "$env:JAVA_HOME\bin\java.exe" -version
.\gradlew.bat --version
.\gradlew.bat run
```

Замените путь `JAVA_HOME`, если Microsoft JDK 21 установлен в другом месте. Проверяйте `JVM` в выводе Wrapper. Одновременно запускайте только одну сборку в этой рабочей копии: параллельные `clean`/компиляции используют общие outputs.

Обычный запуск выбирает новый seed. Для повторяемой диагностики:

```powershell
.\gradlew.bat run --args="--dev --seed=42"
```

`--no-audio` отключает аудиоустройство, `--ai-player` передаёт машину игрока боту. Эти параметры, фиксированный seed, `--smoke-seconds`, `--benchmark-seconds` и `--config-dir` требуют `--dev`; неизвестные аргументы завершают запуск ошибкой. `--config-dir=<путь>` предназначен для локальных экспериментов с балансом. В обычном запуске действуют встроенные конфиги.

## Управление

Начальные назначения; после переназначения актуален экран **Controls**.

| Действие | Клавиатура / мышь | Xbox-совместимый профиль |
|---|---|---|
| Газ | W | RT |
| Тормоз / задний ход | S | LT |
| Руль | A / D | Левый стик |
| Ручник | Space | X |
| Турбо | Left Shift | B |
| Пулемёт | Левая кнопка мыши | LB |
| Выбранное оружие | Правая кнопка мыши | RB |
| Предыдущее / следующее оружие | Q / E | D-pad влево / вправо |
| Homing / Power / Mine / Napalm / Ballistic / Cannon | 1 / 2 / 3 / 4 / 5 / 6 | D-pad влево / вправо |
| Freeze: обездвижить на 2 с | Z | D-pad вверх |
| Shield: снять Freeze, защита 2,5 с | F | A |
| SPECIAL выбранного шасси | C | D-pad вниз |
| Вид назад | V | Y |
| Восстановление машины | Удерживать R | Удерживать View / Back |
| Пауза / возврат | Esc | Menu / Start |

Баллистика: нажмите 5 и ПКМ. Ближайшая видимая машина впереди до 70 м выбирается
сразу, без ожидания LOCK. Четыре заряда падают сверху и умеренно доворачивают за
одной выбранной целью; резкий манёвр и укрытие позволяют спастись. HUD показывает
BALLISTIC TARGET. Если цели нет, FORWARD SALVO означает удар в 40 м перед машиной.
Наземные отметки обновляют прогноз попаданий по мере движения зарядов.

Способность срабатывает отдельным нажатием без модификатора; удержание не повторяет активацию. Одновременно нажатый Shield имеет приоритет над Freeze. Прямой выбор оружия имеет приоритет над Q/E и применяется перед выстрелом. Shield снимает Freeze и захват; после окончания контроля даётся 3 с иммунитета. X на клавиатуре свободна. Настройки и gamepad используют schema 4; миграция сохраняет назначения и оставляет конфликтующие новые действия неназначенными с сообщением в Controls.

SPECIAL Rivet — фронтальная ударная волна, Grinder — контактный захват, Spark — рывок с оставленной бомбой. Их готовность, активная фаза и перезарядка отражаются отдельной иконкой.

В меню доступны мышь, стрелки и Enter, либо D-pad и A; B возвращает назад. Потеря фокуса и отключение активного геймпада вызывают паузу. Если машина легла на бок или крышу, удерживайте газ, задний ход либо руль: на свободной ровной поверхности она встанет на колёса за 1–2 секунды без штрафа HP. Ручной возврат по R / View / Back сохраняет условия удержания, скорости и свободной позиции; в старой арене он стоит 15 HP, в кампании ресурсы сохраняются. Турбо требует контакта с землёй и энергии.

F1 — подсказка, F3 — счётчики диагностики и сырые оси контроллера, F4 — навигационный граф, F12 — снимок экрана. Настройки включают громкости, разрешение, fullscreen/VSync, MSAA 0/2/4/8, силу тряски, чувствительность и dead zone. Новый профиль выбирает fullscreen до 1920×1080 и MSAA 4; существующие настройки сохраняются. Изменение видеорежима требует подтверждения; через 10 секунд без подтверждения восстанавливается прежний режим.

Поддержка профиля GLFW реализована, но конкретную модель и отключение физического контроллера нужно подтвердить в [протоколе приёмки](docs/ACCEPTANCE.md). Файл `gamepad.json` в каталоге данных позволяет задать оси, кнопки и диапазон триггеров; это техническая настройка профиля, а не автоматическое доказательство совместимости всех геймпадов.

## Проверки

```powershell
.\gradlew.bat clean test physicsTest verifyAssets --no-daemon --console=plain
```

| Задание | Что проверяет | Отчёт |
|---|---|---|
| `test` | Чистая логика, конфиги, ввод, аудиоресурсы и ограничения эффектов; отдельные тесты используют doubles | `build/reports/tests/test/index.html`, `build/test-results/test/` |
| `physicsTest` | Реальные Minie/Bullet тела, движение, столкновения, маршруты и 10 seeded матчей без окна | `build/reports/tests/physicsTest/index.html`, `build/reports/ai-batch.json` |
| `verifyAssets` | Строгие конфиги, WAV/шрифт/материалы, SHA-256, происхождение, тексты лицензий и Windows natives | `build/reports/assets/verification.json`, `manifest.json`, `asset-register.csv`, `third-party/` |
| `smokeTest` | Автоматический сценарий в настоящем окне с аудио и повторными матчами | отдельный диагностический профиль в каталоге данных |

`check` включает `test`, `physicsTest`, `verifyAssets`. Ошибка загрузки native-библиотеки является ошибкой проверки. `TECHNICAL_PASS` в отчёте ресурсов не заменяет художественное одобрение и проверку прав на распространение.

Для графического smoke нужен активный рабочий стол и пригодные GPU/аудиоустройство:

```powershell
.\gradlew.bat smokeTest --no-daemon --console=plain
```

Для замера после 30 секунд прогрева предусмотрено 600 секунд повторяющихся боёв в полноэкранном режиме 1920×1080 и с выключенным VSync. В процентили входят кадры активного боя; загрузка и результаты учитываются в длительности сценария отдельно:

```powershell
.\gradlew.bat run --args="--dev --seed=42 --ai-player --benchmark-seconds=600"
```

Smoke, benchmark и `--showcase` несовместимы в одном запуске. `--dev --showcase` записывает 40-секундный диагностический ролик и снимки стадий HP в отдельном профиле; первые 12 секунд — явно подписанная постановочная галерея HP, затем реальные команды оружия через основной MatchRuntime. Звуковая дорожка реконструируется из фактически запущенных игровых семплов; это не запись системного звука или точного OpenAL/HRTF микса. Эта запись не используется для измерения производительности. Они используют новый `%LOCALAPPDATA%/WreckRiff/diagnostics/run-<UUID>` и не перезаписывают обычные настройки/статистику. Автоматический сценарий не заменяет полный бой человеком, физический геймпад или оценку владельца. Статус фактического выполнения каждого сценария указан в [ACCEPTANCE](docs/ACCEPTANCE.md).

Для готового пакета `tools/test-windows-benchmark.ps1 -ZipPath <ZIP> -Arena <ID> -Seconds 600` проверяет новую распаковку указанного ZIP и измеряет память фактического игрового процесса. Итог — `build/reports/windows-benchmark-<ID>.json`; журнал и samples находятся в его `runRoot`. Во время замера окно игры должно оставаться доступным, без сворачивания; другие тяжёлые проверки запускать отдельно. Короткий запуск не получает релизный PASS. Полные условия шести замеров и 30-минутного soak описаны в [PERFORMANCE_DIAGNOSTICS](docs/PERFORMANCE_DIAGNOSTICS.md).

После `packageWindows` проверить отказ готового EXE при неверной схеме arena:

```powershell
.\tools\test-invalid-config.ps1
```

Helper использует отдельный dev-config в `build` и диагностический профиль. Успех проверки означает exit 1, ровно одну ожидаемую `Invalid config arena` ошибку и отсутствие вторичного render/shutdown failure; отчёт — `build/reports/negative-launch.json`.

## Windows app-image и ZIP

```powershell
.\tools\prepare-windows-release.ps1
$build = Get-Content .\build\reports\release-build-verification.json -Raw | ConvertFrom-Json
$zip = (Get-ChildItem -LiteralPath (Join-Path $build.buildRoot 'distributions') -Filter 'WreckRiff-*-windows-x64.zip' -File).FullName
Get-FileHash -Algorithm SHA256 $zip
```

Подготовка выполняет `clean test physicsTest verifyAssets` и `packageWindows` в отдельном `build/release-output/<ID>`, сохраняя прежние отчёты и сборки. После первого заполнения Gradle cache она работает offline. В подкаталоге `distributions` находятся app-image, ZIP и `.sha256`. Версия задаётся в `build.gradle`; исходники, JAR, ZIP и доказательства проверок связаны хешами. `reports/package-verification.json` подтверждает структуру. Сама упаковка не запускает игру и оставляет статус кандидата в релиз.

Проверка готового EXE в настоящем окне, включая 20 повторов матча:

```powershell
.\tools\test-windows-package.ps1 -ZipPath $zip -Mode Smoke -Seconds 600
```

Сценарий распаковывает окончательный ZIP в новый путь с пробелами и кириллицей, временно запрещает запись только в эту копию и исключает внешнюю Java из окружения дочернего процесса. Затем восстанавливает права. Отчёт `build/reports/windows-package-Smoke.json` связывает запуск с ZIP и bundled runtime. Это не заменяет испытание на другой чистой Windows. Отдельные `NormalNew`, `NormalMigrated`, `NormalContinue` запускают EXE без `--dev` для настоящих пользовательских сценариев; правила полного gate и экспорта доказательств находятся в [PERFORMANCE_DIAGNOSTICS](docs/PERFORMANCE_DIAGNOSTICS.md).

[Windows CI](.github/workflows/verify.yml) проверяет Wrapper, запускает тесты, проверяет ресурсы и создаёт пакет; отчёты и ZIP сохраняются как artifacts задания. Автоматического релиза или публикации в Steam нет. Будущая передача описана в [STEAM_HANDOFF](docs/STEAM_HANDOFF.md).

## Данные и диагностика

Обычный каталог данных — `%LOCALAPPDATA%/WreckRiff`; при отсутствии `LOCALAPPDATA` используется `<user.home>/.wreckriff`.

| Путь | Содержимое |
|---|---|
| `settings.json` | Версия схемы, видео, громкости, клавиши, чувствительность и dead zone |
| `stats.json` | Schema 3: завершённые матчи, рекорды по аренам, прогресс кампании и checkpoint одной атомарной записью |
| `gamepad.json` | Профиль осей, кнопок и диапазона триггеров |
| `logs/` | Диагностические логи |
| `captures/` | Реальные снимки по F12 и диагностическим сценариям |
| `cache/natives/` | Извлечённые native-библиотеки; при недоступности предусмотрен временный каталог |
| `diagnostics/run-<UUID>/` | Изолированные данные автоматического smoke/benchmark |
| `launch-summary.json` | Факты обычного запуска и штатного выхода; без автоматической приёмки |

Повреждённые settings/stats сохраняются отдельно; прогресс восстанавливается из последнего пригодного backup либо начинается с defaults. Файл будущей версии схемы сохраняется без перезаписи. При недоступном каталоге настройки остаются в памяти с сообщением об ошибке. Сломанный профиль геймпада сохраняется, используется встроенный профиль. Настройки и gamepad версий 1–3 мигрируют в schema 4 с резервной копией; конфликтующая новая привязка отключается с уведомлением в Controls. Запись игровых данных в каталог установки не требуется по реализации; запуск с реальным запретом записи проверяет packaged smoke.

## Исходники и ресурсы

Одна симуляция 120 Гц владеет единственным `PhysicsSpace`; рендер читает её состояние. Правила хранятся в `src/main/resources/config/`. Геометрия автомобилей/арены и вспомогательные SFX создаются из исходников; боевые SFX подготовлены из локальных CC0-записей. Текстуры Poly Haven 2K, Roboto Condensed и Metalmania Kevin MacLeod включены локально с происхождением и лицензиями. `processResources` готовит ресурсы без скачивания музыки, текстур или шрифтов; оригинальные генераторы 0.1 сохранены в `docs/asset-history/`.

Проект не содержит игрового контента Twisted Metal 4. [ASSET_REGISTER.csv](docs/ASSET_REGISTER.csv) — исходный индекс происхождения, а полный реестр создаётся `verifyAssets` в `build/reports/assets/asset-register.csv` и включается в пакет как `reports/asset-register.csv`. Он содержит автора/источник, packaged path, SHA-256 с областью хеширования, условия/текст лицензии, attribution и статус. Для runtime-геометрии packaged path пуст, `artifact_form` указывает генерацию в памяти, а SHA явно относится к исходнику генератора, а не к mesh или class-файлу. Отдельная лицензия на оригинальный контент не присваивается автоматически.

Музыкальное происхождение: [AUDIO_DESIGN](docs/AUDIO_DESIGN.md); зависимости и оставшиеся вопросы распространения: [THIRD_PARTY_NOTICES](docs/THIRD_PARTY_NOTICES.md). Музыка, визуальный стиль и управление ожидают личной оценки владельца.

Текущий утверждённый контракт: [RELEASE_PLAN](docs/RELEASE_PLAN.md), [арены и боссы](docs/ARENAS_BOSSES_IMPLEMENTATION_SPEC_RU.md), [три шасси](docs/VEHICLES_MVP_SPEC_RU.md). Сохранённое поведение описано в [MVP_SPEC](docs/MVP_SPEC.md), [V0_4_PLAN](docs/V0_4_PLAN.md) и [DECISIONS](docs/DECISIONS.md); при конфликте применяется текущий релизный план.
